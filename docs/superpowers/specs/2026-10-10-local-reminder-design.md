# 本地桌面提醒工具设计

## 目标

开发一个仅在 Windows 本机运行的桌面提醒工具。用户可以建立多个提醒事项，按固定间隔或固定时间点触发，并在屏幕右上角看到自绘提醒弹窗。

## 功能范围

### 提醒事项管理

- 创建多个独立提醒事项。
- 每个事项包含提醒内容、提醒方式、重复规则和启用状态。
- 支持编辑、删除、启用和暂停。
- 数据保存到用户本机，重新启动软件后继续保留。

### 提醒方式

1. 固定间隔
   - 以分钟或小时设置间隔。
   - 从事项启用或保存时开始计算下一次提醒。
2. 固定时间
   - 设置每天的一个固定时间点。
   - 配合重复规则决定哪些日期触发。

### 重复规则

- 每天。
- 仅工作日，即周一至周五；不额外识别法定节假日。
- 自定义星期，可任意选择周一至周日。

### 通知行为

- 到点后在当前屏幕工作区右上角显示无边框悬浮弹窗。
- 弹窗显示提醒内容和关闭按钮，停留一段时间后自动消失。
- 多条提醒同时触发时按顺序向下排列，避免彼此遮挡。
- 电脑休眠或软件未运行期间错过的提醒不补发；恢复运行后计算下一次有效触发时间。

### 后台运行

- 关闭主窗口时隐藏到系统托盘，定时器继续工作。
- 托盘菜单提供“打开”和“退出”。
- 本版本不包含开机自启动。

## 不在范围内

- 稍后提醒、完成打卡和历史记录。
- 提醒音效。
- 法定节假日识别。
- 账户、登录、云同步和联网功能。
- 手机端或跨设备同步。

## 技术方案

采用 Electron：

- 主进程负责应用生命周期、系统托盘、定时调度、文件存储和通知窗口。
- 渲染进程负责提醒列表和创建/编辑表单。
- 共享的纯 JavaScript 调度模块负责校验规则与计算下一次触发时间。
- 提醒数据写入 Electron `userData` 目录下的 JSON 文件，采用临时文件替换方式降低写入中断导致数据损坏的风险。
- 渲染进程通过受限的 preload API 与主进程通信，不启用 Node.js 页面直连。

## 数据模型

每条提醒包含：

- `id`：唯一标识。
- `title`：提醒内容。
- `scheduleType`：`interval` 或 `fixedTime`。
- `intervalMinutes`：固定间隔分钟数，仅间隔模式使用。
- `time`：`HH:mm`，仅固定时间模式使用。
- `repeatType`：`daily`、`weekdays` 或 `custom`。
- `weekdays`：自定义星期数组，仅自定义重复时使用。
- `enabled`：是否启用。
- `nextTriggerAt`：下一次触发时间。
- `createdAt`、`updatedAt`：创建和更新时间。

## 调度规则

- 固定间隔事项保存或重新启用时，以当前时间加间隔得到下一次触发时间。
- 固定时间事项从当前时间开始查找下一个符合重复规则的日期与时间。
- 触发后立即计算并保存下一次时间。
- 定时器按短周期检查到期事项，不依赖长时间单次计时器，以便正确处理系统时间变化和休眠恢复。
- 若检测到事项已过期较久，则不补发，直接推进到下一次有效时间。

## 界面

- 单窗口布局，顶部显示工具名称和“新建提醒”按钮。
- 主区域以卡片或列表展示所有提醒，包含内容、规则摘要、下一次提醒时间和启用开关。
- 新建与编辑使用同一表单，字段随提醒方式和重复规则动态显示。
- 空列表、表单校验错误和本地存储错误均给出明确中文提示。

## 错误处理

- 表单提交前校验内容、时间、间隔和自定义星期。
- 数据文件不存在时自动创建；内容损坏时保留损坏文件备份并以空列表启动。
- 主进程捕获存储和通知窗口错误，并向界面返回可读错误信息。

## 验证

- 单元测试覆盖固定间隔、每天、工作日、自定义星期和跨天计算。
- 单元测试覆盖新增、更新、启停、删除以及无效输入。
- 运行 Electron 开发版本，手动验证托盘、关闭隐藏、退出、右上角弹窗和数据重启保留。
- 构建 Windows 安装包或便携版并做启动检查。
